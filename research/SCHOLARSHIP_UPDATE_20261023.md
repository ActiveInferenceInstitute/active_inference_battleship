## Proposed wording and claim-to-source additions

These are proposed editorial insertions for the implementation owner, not changes applied to the manuscript or guide. Citation keys already exist in [references.bib](../manuscript/references.bib).

**Introduction: model/process distinction** — suitable after the discrete-model vocabulary paragraph; U01 pp. 5–7 and U02 p. 9:

> We distinguish the environment that generates shot outcomes from the assistant's subjective generative model. The likelihood's noise setting describes the assistant's assumptions, while the environment returns deterministic occupancy. This uses discrete active-inference vocabulary without implementing neuronal process dynamics or learning model parameters [@friston2017process; @smith2022tutorial].

**Expected versus realized information** — suitable near the counterfactual-branch explanation; U03 Section 2, pp. 593–594:

> An observed posterior/prior divergence and an observed decrease in entropy are different quantities. Their equality holds after averaging over outcomes under the specified predictive model; it need not hold for either individual outcome [@mackay1992selection]. The displayed expected information therefore describes the current finite hypothesis space and likelihood assumptions.

**Historical GNN context** — suitable at the start of the executable-specification section; U04 Sections 2.1 and 4.2–4.4, plus the pinned software source:

> Generalized Notation Notation (GNN) represents active-inference models in structured text and connects textual, graphical, and executable expressions [@smekal2023gnn]. Here GNN denotes the notation, not a graph neural network. We use an upstream Markdown parser and a project-specific adapter to connect one declared model to the browser runtime [@friedman2026gnnsoftware].

**Guide: what import and controls do** — source-bound wording from the implementation table:

> The build reads the GNN specification with the pinned upstream Markdown parser. A strict adapter checks the supported model fields and compiles default parameters for this Battleship backend. Changing the source requires a new import and build. Source hashes identify the specification and parser files used; they do not certify every upstream backend.
