## Verification design

New browser tests compare downloaded source bytes and SHA-256 with the compiled model, compare plotted coordinates with exported scores for both actors/themes, verify tick alignment and label containment, and confirm sandbox inspection preserves replay bytes. A deliberately displaced DOM point must fail the same coordinate measurement before restored state passes.

Real-file metadata and edition checks reject a wrong organization, title, repository, invented DOI, missing future-release language, and wrong hyperlinks. Existing numerical, real-parser, page-overflow, native Word, math/menu, and mutation checks remain active.

Screenshot matrix tests are split by view/theme. Desktop pointer tests are split by theme/motion setting and selected in the desktop project; touch projects test applicable input behavior. Complete browser workflows have a bounded two-minute case budget for real analysis, viewport captures, and browser cleanup. Individual UI assertions retain their 10-second limit, and fleet workers retain their 30-second runtime timeout. These workflow limits do not replace the separate performance gate. Every accessibility assertion and capture remains required, without runtime skips. Early aggregate timeouts, stale-input rejection, and restart-interrupted evidence are preserved separately; later acceptance requires complete fresh checks.

`bun run test:browser-matrix` reads the actual 70-case Playwright inventory and runs each new case in its own CLI/browser process. It retains the real report, exact case identity, report digest, application/test/build bindings, and a separate orchestration digest. Resuming requires matching bytes and a genuine passing result for that exact case. Empty selections, wrong projects, duplicated cases, incorrect totals, failing results, and modified report files are rejected. Failures stop execution and unaccepted attempts remain available.

An explicit compatibility path can reuse clean completed reports from the earlier file-batch runner. It checks the saved original runner, every application/test/build input, the original receipt, and the complete passing report. It never adopts a failed batch. Changing only the orchestration implementation does not invalidate otherwise identical code under test; the new orchestration is bound separately. The final record accounts for every configured case exactly once. It does not claim that every preceding process passed or that one uninterrupted run survived host restarts.
